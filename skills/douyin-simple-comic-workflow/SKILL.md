# 抖音简洁漫画工作流 v0.7-library-68

The selected SB executes from its annotated YAML template. Geometry is never reconstructed from a layout name or a generic grid. Every visible text-container instance is annotated and bound by `bubble_id`, including separate phone messages, unboxed display text, and prop labels. First render a complete layout-and-text proof and pass preflight, then generate scene assets per panel and assemble them deterministically. Synthetic proof bindings establish layout capability only; real speaker/prop ownership and final mobile quality require actual-image evidence.

Use this skill when the user wants a new Chinese story, article, or copy turned into a static Douyin image group. The default visual mode is `douyin_simple_comic`. This skill produces still PNG pages and a delivery package; it does not make video, audio, timelines, MP4, SRT, transitions, or platform posts.

All 68 source layouts are annotated individually. Read [the library contract](references/comic-layouts/executable-library.md) and `template-index.yaml` before using a newly integrated layout. Annotation completeness, deterministic geometry proof, full text/effect execution, and actual-image acceptance are separate states. An `execution_requirements` entry with no actual evidence blocks full execution. An index entry or nonempty `selected_layout` never establishes a pass.

## Run boundary

Work in an isolated run directory supplied by the user or created for the task. Preserve existing approved pages, character references, prompts, storyboards, delivery files, and project state. Do not overwrite an old page just because a new run uses a similar story. Use the existing project assets only when the user explicitly selects them and bind their actual reference paths.

If the request lacks a source text, an output location, or an existing character reference that is required to keep identity, ask one minimal clarification only when the missing information would change the plot or make image generation impossible. Otherwise proceed with the defaults below.

## Bundled storyboard authority

Before this skill generates characters, pages, or prompts, it must load and execute its own bundled storyboard selector:

- selector: `scripts/prompt_style.py`
- index: `references/comic-layouts/layouts.json`
- prompt files: `references/comic-layouts/SB-001.md` through `SB-068.md`

The bundled pool is the sole storyboard authority. It contains exactly 68 entries from the `comic-storyboard` category. The selector must validate the pool before choosing a layout and must write a handoff artifact named `storyboard-decision.yaml` (or an equivalent path supplied for the run) containing page count, positive panel counts, real `SB-*` IDs, `layout_name`, `layout_source: bundled-internal-comic-layouts`, `selection_reason`, `selected_by: douyin-simple-comic-workflow`, `internal_layout_pool: 68`, and ordered panel content.

The workflow may analyze the copy to supply story beats and minimum-sufficient constraints, but it must not call another storyboard Skill, read an external storyboard library, or use an unregistered fallback. If the internal index or any matching `SB-*.md` is missing, invalid, or inconsistent, stop before image generation and report the blocking reason.

The bundled layout-to-bubble source adapter is `references/comic-layouts/bubble-constraints.yaml`; its paired compatibility contract is `references/comic-layouts/bubble-execution-profiles.yaml`. Read `source_rule_level` and `visual_reference_only` before treating source material as evidence. A preview or description alone is not executable geometry. Reviewed annotations in `executable-templates/SB-###.yaml` supply the preview contract; workflow-authored compatibility profiles never override it or count as original SB rules. A missing/non-executable required contract blocks composition.

The per-layout executable template registry is under `references/comic-layouts/`: `previews/` contains copied, untouched SB previews; `source-notes/` contains the matching SB markdown notes; `executable-templates/SB-###.yaml` contains structured panel and bubble annotations; and `template-index.yaml` is the index consumed by validation. Template evidence distinguishes `observed`, `inferred`, and `unknown`. A reviewed template may additionally declare `structure.units`, `structure.nested_units`, `overlays`, `text_zones`, and `style_contract` for polygons, broken frames, phone columns, headers, gutters, and other visible structure. Unknown geometry or bubble ownership is a blocking review state, not permission to invent a default box. Run `scripts/check_executable_templates.py` before wiring templates into text composition.

Each execution declares one `match_policy`: `structure_exact` preserves the preview's panel geometry, count, ratios, reading order, and declared structural treatments while allowing story content to change; `pixel_reference` is a benchmark mode that also preserves preview sample elements; `adapted` permits a deliberately different composition and can never be reported as an exact storyboard match. `structure_exact` and `pixel_reference` block unannotated templates and require the preview image to be passed as an actual image reference. A `selected_layout` value alone is never proof of execution.

Native-source compilation preserves the full preview canvas and its coordinates. A 3:4 delivery preference does not authorize cropping an SB implicitly. When the user has selected 3:4 full bleed, use `prompt_style.py --approved-3-4-adaptation`; it calls `scripts/template_canvas.py`, excludes the instructional header, scales the artwork uniformly, records clipped panel boundaries and same-panel bubble fitting, and compiles `match_policy: adapted`. Keep the source YAML and previews unchanged. Passing this approved target leaves `source_reference_geometry_match: failed`; source fidelity, target compliance, and human acceptance remain separate. See [the native proof and adaptation rules](references/workflow-rules.md#native-layout-proof-v06).

The storyboard `panel_count` is a planning field for that page and must equal its `panels` list. It is not a claim about the number of visible borders in the rendered base image. At handoff and delivery level, keep these fields separate: `planned_story_units` is the total planned story units, `planned_panel_count` is the sum of the storyboard page counts, `visible_panel_count` is the audited count of panels visibly present in the final base images, `panel_count_delta = visible_panel_count - planned_panel_count`, and `panel_count_reconciliation` records both sources and the explanation for any difference.
## Execution

1. **Read and scope the source.** Save the exact Chinese copy in the run's `source/article.md`. Produce an analysis file that separates `source_facts`, `reasonable_inferences`, `design_additions`, and `open_questions`. Extract theme, core events, relationships, timeline, scenes, actions, emotion turns, turning points, visualizable beats, and abstract content. Do not turn an inference or a design addition into a source fact.
2. **Create or bind characters.** Make one card per important character with stable IDs (for a new run use a new namespace such as `N01`, `N02`; never reuse an unrelated project's `C01`/`C02`). Record age/version, appearance, provisional wardrobe, identifying features, props, emotions, and source boundaries. Existing characters may be reused only with their actual card and reference-image paths. Generate at least one reference sheet for each character when image generation is available; record `generated`, `not-reviewed`, and the actual path. If references are required but cannot be passed as image inputs, stop before page generation.
3. **Run the bundled storyboard selector and accept its handoff.** Analyze the copy for story functions and minimum-sufficient page/panel needs, then execute `scripts/prompt_style.py` against the local 68-layout pool. Validate `storyboard-decision.yaml`: page/panel counts are positive and minimum-sufficient, every page has a real compatible SB layout, and every panel has one main action or emotion. Dynamic page and panel counts remain allowed, but the decision owner is this workflow's bundled selector.
4. **Consume the bundled handoff without redesign.** Read the handoff and copy its planning `panel_count`, `panels`, `layout_id`, `layout_name`, `layout_source`, `selection_reason`, and `selected_by` into `storyboard/pages/<PAGE>.yaml` and prompts unchanged. Check only the bundled internal index and matching prompt file to validate the handoff. Do not choose a replacement SB, add padding panels, or reinterpret the page function. If the handoff is incompatible or invalid, stop and return the handoff error. Do not overwrite the planning count with a later visible-panel audit.
5. **Hand off to prompts.** Derive each page prompt from the accepted storyboard without changing `panel_count`, `panels`, or any SB field. Carry forward the simple-comic controls: `visual_mode: douyin_simple_comic`, `visual_density: low`, `background_level: minimal`, `mobile_reading_priority: true`, page `main_focus`, per-panel `focus`, `secondary_focus`, `key_objects`, `key_objects_max` (interpreted per panel), and `text_readability`. Keep one main action or emotion per panel and use only location cues in the background.
   The selector must compile the accepted SB into an executable `execution_contract` before generation by reading `executable-templates/SB-###.yaml`: canvas size, exact count, ordered panel IDs, normalized and pixel `xywh` bounds, ratio, `geometry_type`, polygon vertices when declared, bubble bindings, style contract, preview reference path, and the selected `match_policy`. The generated prompt must carry every boundary and the hard constraints `allow_add_panels: false`, `allow_delete_panels: false`, `allow_merge_panels: false`, and `allow_split_panels: false`. `prompt_style.py` must fail clearly when the selected template has no annotated panel geometry; it must not fall back to a vertical stack, equal grid, or any other workflow-authored geometry.
   Before scene generation, render every selected template's complete layout-and-text proof using its actual instance IDs, polygons, known tails, and fonts. Resolve overflow, semantic conflicts, and missing bindings here. Mark proof regions `synthetic: true` and `actual_image_checked: false`; they are not evidence of actual story speakers or props. Run [scripts/preflight_preview_text.py](scripts/preflight_preview_text.py) with `--template`, `--text-plan`, optional `--text-layout`, and `--output`; require an accepted complete proof plus `generation_ready: true` and exit code 0. Exact requests also block unknown required tails or unavailable brush fonts. The gate never rewrites types, text, or geometry. Compile every bubble's `bounds_px`, shape/style, allowed types, known tail geometry, avoidance rules, and `reserved_no_subject_zones` into the prompt. Scene assets leave these zones quiet and keep faces, hands, and key props outside them. Post-layout composition owns bubble bodies, tails, and text. Font measurement remains preliminary and never replaces real-page checks.
6. **Generate actual base images.** When an image generator is available, pass every bound reference image as an actual image input, not just a path in the prompt. In `structure_exact` or `pixel_reference`, generate scene assets per declared unit and assemble the page with a deterministic template executor; the image model does not decide panel count, borders, gutters, phone shells, headers, polygon masks, or nested-unit placement. Keep style, palette, canvas, and character versions from the approved run data. If the generator is unavailable or a required reference cannot be passed, stop at prompts and report that images were not generated. Never mark a prompt as a finished image.
   After generation, record `actual_panel_geometry` from the no-text base image and run `scripts/audit_storyboard_layout.py`. The audit must compare the rendered image against the execution contract and, when available, the normalized preview structure: count, `xywh` boundaries, polygons, aspect ratios, nested units, reading order, and declared style treatments. Report `preview_structure_match`, `preview_style_match`, and `storyboard_layout_match` separately. Any deviation sets `storyboard_layout_match: failed`, regardless of whether `selected_layout` is present. Missing actual geometry also fails. This audit runs before dialog/text repair; it must not modify the base image. A geometry pass alone never establishes complete execution: require `execution_style_match: passed` and `full_template_execution: passed` after linking the actual final text reports. SB-013's diagonal panel outline does not prove foreground breakout. A required crossing uses native transparent artwork, a declared allowed receiver panel, and hash-bound visible pixels on both sides of an executed edge; missing crossing evidence blocks complete execution.
   For a newly integrated template or renderer, finish one real-page pilot after the complete proofs pass before extending the batch. Replace every synthetic binding with confirmed same-panel regions measured from the generated scenes. Actual geometry requires `measurement_evidence` bound to the base `image_sha256`, an accepted measurement method, and `geometry_observed_from_image: true`. Copied target/transform metadata is not measurement. A style contract alone cannot pass style: record separate hash-bound `style_verification` from visual comparison. See [the evidence schema](references/output-schema.md#base-image-measurement-evidence); missing evidence blocks acceptance even after deterministic assembly. Unknown source fonts, occluded edges, and manually traced polygons retain their declared uncertainty even when the target draws successfully.
7. **Select and compose text.** Preserve `narration_text`, `dialogue_text`, `note_text`, and `text_placement`; link each source entry once through `text_blocks`. For preview matching, resolve `layout_id` → executable template → existing `bubble_id` → that bubble's `panel_id`, `allowed_text_types`, `shape`, `bounds`, `position`, `tail`, and `visual_style`. Keep field evidence `observed`, `inferred`, or `unknown`; do not create bubbles absent from the preview, invent unknown tails, or replace incompatible text with an ordinary long box. Semantic source type remains unchanged: a preview speech bubble does not authorize converting narration to dialogue. Missing/incompatible zones remain blocked or explicitly adapted under the template's fallback policy. The compatibility profile must also load, but it cannot override an annotated preview contract. Follow [the preview contract rules](references/workflow-rules.md#preview-bubble-contract-v05) and its coordinate-transform requirements.
   Call [scripts/text_compositor.py](scripts/text_compositor.py) with the existing base, linked text plan, layout config, a candidate output PNG, and reports. Record source/target contract geometry separately from actual `body_rect`/`drawn_geometry`; declared `bubble_id` or copied contract fields are not render evidence. Do not regenerate or overwrite the base; report `base_image_modified: false`. Preserve source wording, speaker/channel ownership, protected faces/hands/key props, and panel boundaries. Unknown tails remain undrawn and cannot count as verified tail fidelity.
   Before promotion, run [scripts/audit_preview_bubbles.py](scripts/audit_preview_bubbles.py) on the candidate plan and render report. Require accepted placement plus independently reported bubble ID, panel binding, shape, position, bounds, tail, and visual-style checks. Any failed or unknown required exact-match check blocks an exact claim. An adapted/clipped result may pass target placement or style checks, but retains failed/pending source-preview geometry status. Keep human visual acceptance pending; metadata agreement does not establish pixel-level equality.
   The formal entry requires explicit pixel coordinates for the anchor or resolved bubble contract and protected regions (`rect_format: xywh|xyxy`) plus a final `panel_id`; `anchor: auto` is planning-only. Execute observed tail polygons according to `anchor_kind`: speaker tails require a confirmed visible same-panel speaker region, prop-label tails require a confirmed same-panel prop region, and chat UI nibs require a confirmed phone screen/channel. Unknown ownership remains blocked. Brush display text uses the bundled OFL-licensed `assets/fonts/mashanzheng/MaShanZheng-Regular.ttf` only with hash-bound `brush_font_verification`; the chosen brush family does not prove equality with the unknown preview font. See [the v0.6 binding and font schema](references/output-schema.md#native-layout-proof-v06). A carrier requires matching `anchor.carrier_id`/`carrier.asset_id`, a carrier polygon, and a writable rect; missing or ambiguous carrier geometry blocks placement. Existing pages use a recorded outer-polygon bounding-box/writable-rect adapter; exact writable-polygon point containment is outside this draft. The entry reports actual drawn geometry, collision results, dedupe status, and `page_acceptance_status`. Unsafe content is removed before a blocked page is written. `published` remains `false`.
8. **Check and deliver.** Verify story order, character identity, props, text content and ownership, panel reading order, real SB structure, absence of unauthorized plot additions, and image dimensions. A final image is complete only when it exists, is PNG, is 1080×1440 (3:4), and contains post-layout text. Write a continuity/technical report and a delivery manifest with page order, SB IDs, the separate `planned_story_units`, `planned_panel_count`, `visible_panel_count`, `panel_count_delta`, and `panel_count_reconciliation` fields, base/final paths, statuses, and `published: false`. Keep human visual acceptance pending until a person reviews the images.

9. **Enforce one final image per page.** Before delivery, run `scripts/check_page_uniqueness.py` against the run manifest. The default contract is exactly one canonical final PNG for each `page_id`, named `<PAGE_ID>-final.png`. A retry is a candidate operation: write it under `pages/candidates/<PAGE_ID>/`, check it, and promote only the selected candidate with `scripts/finalize_pages.py`; never list every candidate in the delivery manifest. Variants are allowed only when the user explicitly requests them and the run records that request; they remain outside the default final-page list. The check also compares `story_beat_id` values and adjacent panel action/emotion/camera metadata so repeated story beats or visually identical adjacent panels become `duplicate_story_check: needs_review` instead of silently producing extra pages.

## Dynamic panel policy

Use `panel_count_policy: minimum_sufficient`. For every page write `panel_count`, `panel_count_reason`, `required_story_beats`, `panel_addition_log`, `narrative_function`, and `panels`. `panel_count` must equal the number of `panels` entries.

Add a panel only when it fixes a concrete reading problem: an unclear action or relationship, a missing emotional transition, an unclear appearance/use/change of a key prop, text that remains crowded after shortening and layout adjustment, or a core event that cannot otherwise be understood. Every added panel must include both `reading_problem_solved` and `why_existing_panels_are_insufficient`. Stop adding when the next panel would not improve understanding, emotion, or reading rhythm. Empty `panel_addition_log` is valid when no panel was added.

Planning and visible-panel reconciliation is a separate delivery check:

1. `planned_story_units` records the story units selected by the storyboard handoff.
2. `planned_panel_count` is the sum of the page-level planning `panel_count` values; each page still requires `panel_count == len(panels)`.
3. `visible_panel_count` is measured from the final base images after the selected SB layouts are expanded, including documented inset or split panels.
4. The counts may differ when the final base conforms to the selected SB structure. A documented and explainable difference does not automatically fail the run.
5. If the difference cannot be explained from the selected SB structure and the final base audit, block publication and report the unresolved reconciliation. Never alter a planning count merely to hide a structural difference.

## Final image uniqueness and candidate handling

`page_id` identifies one story page, not one render attempt. The default delivery invariant is:

```yaml
page_id: P10
story_beat_id: B14
candidate_image_count: 0
final_image_count: 1
generated_variants: 0
duplicate_story_check: passed
retained_final_image: P10-final.png
```

The canonical path is `pages/final/<PAGE_ID>-final.png`. Names such as `P10-final-v001.png`, `P10-final-v002.png`, and later retry numbers are not default final outputs. They are legacy or candidate artifacts and must not enter a new delivery manifest. A retry must go under `pages/candidates/<PAGE_ID>/` (or an equivalent run-internal candidate directory), and after the check the workflow retains one image by moving or copying it to the canonical filename. The workflow does not delete historical run directories retroactively.

The uniqueness check must fail the manifest when a page is listed twice, when `final_image_count` is not `1`, when `generated_variants` is nonzero without an explicit user request, or when `retained_final_image` is not the canonical filename. It must report `needs_review` when the same `story_beat_id` is attached to more than one page, or when adjacent panel metadata repeats the same action, camera function, and emotion. An SB's expanded or inset structure may create multiple visible panels inside one page, but it does not create multiple final PNGs. If adjacent panels have no new action, expression, prop, or camera function, reduce the panel plan instead of generating a duplicate image.

Historical versioned images may remain in an old run for audit purposes. They are not evidence that a new run may deliver multiple finals. `scripts/check_page_uniqueness.py` reports such legacy files without modifying them.

## Text and status invariants

Keep `narration_text`, `dialogue_text`, and `note_text` separate. Use `text_strategy: post-layout` and linked `text_blocks` as defined in [references/output-schema.md](references/output-schema.md#text-blocks-v02-draft). `bubble_style` records a rule decision and is consumed by [scripts/text_compositor.py](scripts/text_compositor.py). When a style or type cannot be determined, use only the selected profile's declared fallback policy. Record `fallback_used: true`, a non-empty `fallback_reason`, and `render_source: fallback`; a missing/non-executable profile blocks placement rather than silently drawing a warm-white long box. Preserve any physical-carrier binding. If no safe area or carrier is available, keep placement unresolved instead of hiding a face, action, or prop. A page prompt starts as `prompt_status: draft`, `render_status: not-generated`, `final_status: not-generated`, `check_status: not-checked`; update those fields only after the corresponding artifact exists and has been checked. If a page fails, repair the smallest affected unit: recompose text first for text errors, redo only the problem page for identity or image errors, and never regenerate the whole set without a reason.

At minimum, produce:

- `source/article.md`
- `analysis/content-analysis.yaml`
- `characters/<ID>/character.yaml` and `characters/<ID>/references/`
- `storyboard-decision.yaml` and `storyboard/pages/<PAGE>.yaml`
- `prompts/pages/<PAGE>-prompt.yaml`
- `pages/renders/<PAGE>-base.png`
- `pages/candidates/<PAGE_ID>/` (optional, run-internal only)
- `pages/final/<PAGE>-final.png`
- `reports/continuity-technical-report.yaml`
- `reports/page-uniqueness-report.yaml`
- `delivery/manifest.yaml`
